kornia-3d: projective ICP (`icp_projective_plane`, `icp_projective_plane_with`) runs its association passes on an `F32x8` kernel by default, `IcpKernel::Simd`: eight `f32` lanes, the normal equations summed in `f32` over 128-point blocks and the blocks in `f64`. `IcpWorkspace::new(IcpKernel::Scalar)` keeps the previous `f64` kernel. Solve time per call on the synthetic `bench_icp` scene, single thread on a loaded x86-64 laptop, scalar to SIMD:

| build | association | 160x100 | 320x200 |
|---|---|---|---|
| default (SSE2) | nearest | 12.6 to 5.6 ms (2.3x) | 47.1 to 22.0 ms (2.1x) |
| default (SSE2) | bilinear | 1.24x | 1.29x |
| default (SSE2) | hybrid | 1.49x | 1.47x |
| `-C target-feature=+avx2,+fma` | nearest | 11.7 to 4.7 ms (2.5x) | 47.2 to 18.7 ms (2.5x) |

**This changes the output of RGB-D odometry.** The default no longer reproduces the previous bits: on the test scenes, pose, information matrix and RMSE differ from the `f64` kernel by up to 1.7e-5 relative (rotation 8e-8, translation 6e-6, information 5e-7). Correspondence counts can differ by a few in 1e4 where an `f32` projection rounds to the neighbouring pixel. Dense RGB-D trackers accumulate in `f32` as well (Open3D's tensor RGB-D odometry, ElasticFusion, InfiniTAM). The SSE2 and AVX2 builds give the same bits.
