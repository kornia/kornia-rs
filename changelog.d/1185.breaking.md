kornia-imgproc's `cuda` feature now uses CUDA kernels written in Rust. The first,
`gray_from_rgb_u8`, is compiled to PTX by NVIDIA's cuda-oxide and replaces the NVRTC kernel
behind `cuda::color::gray::launch_gray_from_rgb_u8` (same signature, output byte-identical to
the CPU path). The NVRTC kernel stays as the fallback, used on GPUs older than sm_75
(Maxwell/Pascal, e.g. Jetson Nano/TX2), in builds without the PTX, and if the module fails
to load. The PTX ships in a new crate, **`kornia-oxide-kernels`** (PTX + entry names, no
dependencies by default), together with `OxideError` and a loader for kornia's own launchers
behind its `cuda` feature (hidden, not public API); kornia-imgproc's `cuda` turns on its
`cuda` and `ptx` features. kornia-tensor gains a hidden `impl From<CudaFunction> for
CudaKernel` for that loader. See `docs/cuda-oxide.md`.

- **Building with `--features cuda`.** From crates.io nothing changes: the published crate
  carries the PTX. A kornia-rs checkout or git dependency without it (built by
  `cargo run -p kornia-oxide-kernels --example build_ptx`, which needs the cuda-oxide
  toolchain, `scripts/cuda-oxide/install-toolchain.sh`) still builds: a `cargo:warning` says
  so, and the ported kernels run their NVRTC fallback.
- **`CudaColorError` gains two public variants**, so exhaustive `match`es on it must add arms:
  `TooManyPixels { npixels }` and `Misaligned { what, addr }`. `Compile` now also covers a
  cuda-oxide module that fails to load or stub PTX (message: "CUDA color kernel unavailable").
- **Launcher behaviour.** CUDA color launchers treat zero pixels as a no-op and return
  `TooManyPixels` when the element count passes `u32::MAX`. Every four-pixel
  (word-vectorized) launcher returns `Misaligned` instead of faulting when `src` or `dst` is
  not 4-byte aligned (e.g. a DLPack alias at an odd offset): `launch_gray_from_rgb_u8`,
  `launch_sepia_from_rgb_u8`, `launch_bgr_from_rgb_u8`, `launch_ycc_from_rgb_u8` and
  `launch_rgb_from_ycc_u8`.
- **Examples.** `cuda-fusion`, `cuda-camera-sift` and `cuda-camera-preprocess` now need
  `--features cuda`.
