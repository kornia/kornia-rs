`kornia_3d::pnp::PnPError` gains an `InvalidInput(String)` variant. `refine_pose_lm` returns it for a non-finite world point or start pose, which used to give `Ok` with a non-finite RMSE or pose, and when most points sit on the start camera, which used to fail with `SvdFailed`. An exhaustive `match` on `PnPError` needs a new arm. `LMRefineParams::initial_lambda` and `gradient_tolerance` now act in the local frame `refine_pose_lm` solves in, which is scaled so the median point sits about 1 from the start camera; callers that set non-default values should re-tune them.
