`kornia_3d::pnp` EPnP no longer returns a wrong pose on noise-free data with 5 or more points: the four null-space vectors were paired with the wrong betas (one part used them smallest-first, the other largest-first). On noise-free random scenes it missed by 1 px or more in about 90–100% of cases; with 20 or more points it now fit all tested random non-planar scenes up to a depth of 20 times the object size (farther away it can still miss by up to about 10 px). `solve_pnp_ransac` with an EPnP kernel now applies its refit on such data instead of rejecting it. Exactly planar targets are still a weak case for EPnP, which has no planar (three control point) variant.
